# 상용화 점검

2026-11-13 기준. 코드와 프로덕션 응답, Vercel 환경변수 이름, Supabase 프로젝트 상태만 확인했다. 프로덕션 데이터는 읽거나 바꾸지 않았다. 결제, 가격, 약관 확정, 외부 서비스 가입은 하지 않았다.

판정은 세 가지다.

- **차단**: 이게 그대로면 돈을 받거나 낯선 학생에게 열면 안 된다.
- **주의**: 열어 둘 수는 있으나 운영자가 알고 있어야 한다.
- **괜찮음**: 지금 범위에서는 충분하다.

## 지금 목록이 비는 이유

`/ko/tutors`와 `/en/tutors`의 “튜터 목록을 불러오지 못했어요” / “Failed to load data”는 쿼리 오타가 아니다. 공개 페이지가 미리 연결하는 주소는 `https://gtkzswjeycklicgnygin.supabase.co`이고, 그 호스트는 DNS에 없다. Supabase 프로젝트 `korean-tutor-hub`(ref `gtkzswjeycklicgnygin`, 리전 `ap-northeast-2`) 상태는 `INACTIVE`다. 테이블 목록과 SQL은 “Database is possibly not accessible”로 거절된다.

Vercel 프로젝트 `korean-tutor-hub`에는 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_ANON_KEY`가 production과 preview에 있다. 값은 읽지 않았다. 공개 HTML의 preconnect가 위 프로젝트와 같으므로, 키를 지우고 다시 넣을 문제는 아니다. 같은 조직의 다른 프로젝트 `zz1877zz-cloud's Project`(ref `jlanowxkeppbtshmeivr`)도 `INACTIVE`이고, 이 사이트가 쓰는 주소는 아니다.

코드는 `tutors`에서 `is_active = true`인 행을 고른다. 데이터베이스가 꺼져 있으면 그 요청이 실패하고, 페이지는 오류 문구를 낸다. 빈 목록과 실패는 이미 구분된다. RLS와 행 개수는 프로젝트가 꺼져 있어 확인하지 못했다.

### 승현이 할 설정

1. Supabase에서 `korean-tutor-hub` (`gtkzswjeycklicgnygin`)를 Restore 한다. 행을 지우거나 고치지 않는다.
2. `https://gtkzswjeycklicgnygin.supabase.co`가 다시 풀리는지 본다.
3. Vercel의 URL과 anon key는 그대로 둔다. 프로젝트를 바꿀 때만 둘을 함께 바꾼다.
4. 복구 뒤 `/ko/tutors`를 연다. 오류 문구가 없고, 활성 튜터가 있으면 카드가, 없으면 빈 상태 문장이 보이면 된다.
5. anon 키가 활성 튜터 `select`를 막으면, 그때 RLS만 공개 읽기 허용으로 맞춘다. 이 PR에서는 정책을 바꾸지 않았다.

## 항목

### 인증·권한

- **현재**: 이메일·비밀번호 로그인, Supabase 세션, 관리자 레이아웃은 `profiles.role = admin`이 아니면 `/ko`로 보낸다. 학생·튜터 구분은 `tutors.user_id`로 헤더에서 본다.
- **판정**: 주의. 데이터베이스가 꺼져 있으면 로그인 자체가 되지 않는다.
- **작업**: 프로젝트 복구. 복구 후 관리자 계정 한 명으로 `/admin/tutors` 진입을 확인한다.
- **승현**: 관리자 이메일을 누구로 둘지. 비밀번호 재설정 메일을 켤지.

### 튜터 승인

- **현재**: `/apply-tutor`는 소개를 보여 주고, 전송은 로그인 뒤 `tutor_applications`에 `pending`으로 넣는다. 관리자가 신청을 보고 튜터 행을 만든다. 공개 목록은 `is_active = true`만 보여 준다.
- **판정**: 차단. 데이터베이스가 꺼져 신청도 목록도 안 된다. 흐름 자체는 있다.
- **작업**: 복구 후 신청 한 건을 승인·비활성으로 왕복해 본다. 자동 알림은 메일 키가 있을 때만 나간다.
- **승현**: 승인 기준(얼굴 사진, 48시간 응답)을 약관에 확정할지. 거절 사유를 신청자에게 보낼지.

### 예약·상담

- **현재**: 오작교는 `consultations` insert. 첫 수업 요청은 `POST /api/bookings`로 `pending` 예약을 만든다. 사이트는 결제를 받지 않는다고 화면에 적혀 있다. 예약 메모는 2000자, 튜터 id는 UUID만 받는다.
- **판정**: 주의. 저장은 되지만 결제·일정 확정·리마인더는 없다. 데이터베이스가 꺼지면 둘 다 실패한다.
- **작업**: 복구 후 학생 계정으로 오작교와 예약이 각 받은함에 보이는지 확인.
- **승현**: 예약은 “요청”으로 둘지, 시간 슬롯을 잠글지. 오작교 48시간 응답을 운영 규칙으로만 둘지.

### 결제

- **현재**: 결제 코드, 가격표, 수수료 징수가 없다. `/fees`는 초안이고 “결제가 열리기 전에는 금액이 적용되지 않는다”고 적혀 있다. 체험팩과 추천 슬롯은 판매하지 않는다고 공개 문구에 있다.
- **판정**: 차단, 다만 돈을 받기 시작할 때의 차단이다. 지금처럼 무료 연결만 하면 결제 없음이 맞는 상태다.
- **작업**: 제안만. 결제사를 고르고, 수업료는 튜터 `hourly_rate`를 표시만 하고 플랫폼은 정산 후에 받는 구조가 코드와 맞다. 웹훅, 영수증, 환불 API가 필요하다.
- **승현**: 지금 출시를 “소개와 연결”로 둘지, “사이트에서 결제”까지 할지. 수수료율, 통화, 체험팩 구성과 가격.

### 이용약관·개인정보·환불

- **현재**: `/terms`, `/privacy`, `/fees`가 로케일별로 있다. 수수료 페이지는 “초안”, 버전 0.1, 2026-09-01이다. 지원 화면은 약관·개인정보·튜터 계약 초안에 동의해야 전송된다.
- **판정**: 차단, 유료로 열 때. 무료 연결만이면 초안임을 유지하고 변호사 검토 전이라고 밝히는 편이 맞다.
- **작업**: 제안만. 확정본으로 바꾸기, 사업자 정보·연락처·보관 기간을 채우기.
- **승현**: 사업자 등록 여부, 개인정보 보호책임자, 해외 학생 데이터 이전, 환불은 플랫폼이 들지 당사자 책임인지.

### 에러 처리·모니터링

- **현재**: 목록 실패와 빈 목록은 구분된다. 실패 원인은 사용자에게 보이지 않고, 이번 변경부터 서버 로그에 범위 이름과 짧은 message·code만 남긴다. 비밀키는 로그에 넣지 않는다. Sentry나 업타임 알림은 없다. Vercel Hobby 로그 보관은 약 1시간이다.
- **판정**: 주의. 이번 장애는 로그가 남아 있지 않아 DNS와 프로젝트 상태로 확인했다.
- **작업**: 프로젝트 복구 후 한 번 더 `/ko/tutors`를 열고, 오류가 남으면 Vercel 로그의 `[kth] tutors.list failed`를 본다.
- **승현**: 오류 알림을 메일로 받을지. 로그 보관을 늘릴 플랜을 쓸지.

### 보안

- **현재**: 공개 읽기는 anon key. 서비스 롤 키는 저장소와 Vercel 환경변수 목록에 없다. `RESEND_API_KEY`와 `ADMIN_NOTIFY_EMAIL`은 이 목록에 없고, 없으면 메일은 건너뛴다. `/api/notify`는 로그인 세션이 있어야 하고, 본문은 500자로 자른 뒤 메일 원문을 응답에 넣지 않는다. 예약 API는 UUID와 메모 길이만 검사한다. RLS는 데이터베이스가 꺼져 확인하지 못했다. 관리자 화면은 역할 검사를 한다.
- **판정**: 차단에 가깝다. 2026-11-14에 프로젝트가 다시 켜진 뒤 정책을 읽었다. 다섯 테이블 모두 RLS가 켜져 있다. 활성 튜터 공개 읽기는 `is_active = true`로 맞다. 예약은 `Anyone can view bookings`(USING true)와 `Anyone can create booking`(CHECK true) 때문에 방문자도 읽고 넣을 수 있다. 튜터 행은 `Anyone can insert tutors`(CHECK true)로 누구든 만들 수 있다. 상담과 프로필, 지원서는 본인 또는 관리자 조건이다. 적용하지 않은 제안은 `docs/suggested-rls-migration.sql`이다.
- **작업**: 승현이 그 파일을 승인한 뒤에만 실행한다. 실행 전 백업은 무료 플랜에 자동 일일 백업이 없으니, 승인 전에 스키마를 따로 받아 둔다.
- **승현**: anon key를 브라우저에 두는 현재 방식은 Supabase의 정상 모델이다. 키를 저장소에 커밋하지 말 것. 서비스 롤은 서버 전용으로, 필요할 때만 추가.

### 성능

- **현재**: 목록은 서버에서 한 번 읽고 카드로 그린다. 이미지 히어로는 webp. 튜터 수가 적다는 전제다. 페이지네이션은 없다.
- **판정**: 괜찮음, 수십 명까지. 수백 명이면 주의.
- **작업**: 목록이 길어진 뒤에 페이지 나눔.
- **승현**: 한 화면에 몇 명을 둘지.

### 접근성

- **현재**: 건너뛰기 링크, `lang`, 버튼 포커스 링, `prefers-reduced-motion`, 44px 안팎의 터치 높이, 목록 오류는 `role="alert"`. 대비는 밝은 테마 기준으로 맞춰 두었다.
- **판정**: 주의. 스크린 리더로 오작교 작성부터 전송까지 한 바퀴를 아직 기록하지 않았다.
- **작업**: 복구 후 키보드만으로 목록 → 프로필 → 오작교를 한 번 통과.
- **승현**: 한국어·영어 중 어느 쪽을 출시 기준 언어로 둘지. 둘 다 유지가 현재 상태다.

### 테스트

- **현재**: 자동 테스트는 로그에 남길 오류 요약 두 건뿐이다. `node --test src/lib/supabase-log.test.ts`. 브라우저 테스트와 데이터베이스 테스트는 없다. CI는 Vercel 빌드가 사실상 전부다.
- **판정**: 주의. 출시를 막는 단일 결함은 아니고, 회귀를 못 잡는다.
- **작업**: 로그인·승인·오작교·예약의 수동 확인표를 복구 직후 한 번 돈다.
- **승현**: 자동 테스트를 어느 흐름부터 넣을지. 제안은 예약 API의 UUID 거절과 목록 실패 시 오류 문구다.

### 분석

- **현재**: 페이지뷰, 퍼널, 오류 수집 도구가 없다.
- **판정**: 주의. 출시 자체보다 “어디서 그만두는지”를 모른다.
- **작업**: 제안만. 개인정보를 쿼리스트링에 넣지 않는 방문 수 도구 하나.
- **승현**: 어떤 숫자를 볼지. 제안은 홈 → 목록 → 프로필 → 오작교 전송 → 예약 요청. 후기 수나 평점은 실제 행이 생기기 전에는 보여 주지 않는다.

## 이 PR에서 코드로 한 것

- 목록·홈·사이트맵이 Supabase에 실패하면 서버 로그에 `[kth] … failed`와 짧은 message, code만 남긴다.
- `/api/notify`는 로그인 없이 메일을 보내지 않고, 본문은 500자, 응답에 메일 원문을 넣지 않는다.
- 예약 API는 튜터 id가 UUID가 아니거나 메모가 너무 길면 잘라 저장하거나 거절한다.

목록이 미리보기에서 채워지지는 않는다. 미리보기도 같은 꺼진 프로젝트를 본다.
